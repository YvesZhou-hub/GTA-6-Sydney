# 公共空间夜间照明

本轮先修复完整城市原生夜景中明确不可读的 ICC 剧场前厅。原图保存在开发证据 `reports/daylight-city-first`：顶上已有发光灯条，地板却近乎纯黑。代码检查确认原楼板同时覆盖声学观众厅与公共玻璃前厅，统一使用 `icc_dark`；灯条只有自发光材质，没有实际照亮其他表面的灯。原 prism 顶面法线向上，碰撞高度正常。

`icc/theatre/floor` 现在按既有公共区边界分材质：剧场局部 x≥42.20、z在−36至36米内使用暖灰色程序铺装，其余保留深色观众厅。世界坐标投影让分区在生产空间批处理后仍对齐。没有增加重叠地板、改碰撞顶点、改变0.035米相对标高或建立新的损坏ID；破坏、读档及修复继续作用于原楼板。这里是照片指引的材质重建，不是测量得到的反射率。

## 固定的小范围灯光

新 `public_lighting.gd` 在世界建立后预建 **34盏无阴影灯**，上限40，不为全城每个窗口或灯条创建灯。

- ICC：12盏位于现有红顶前厅的三条线性灯带，覆盖可走楼板；4盏代表 Convention 既有凹入灯组；4盏代表 Exhibition 既有灯组。这20盏公共室内灯白天也工作。
- 海港大桥：10盏对齐已有几何灯头，依赖各自桥面损坏分块，照向桥面。这不等于完整大桥夜景泛光安装复刻。
- 歌剧院：4盏克制的暖白屋壳泛光，配可见短基座。位置为上平台外缘局部 x±58米、高出平台0.5米，绑定实际承载的上平台分块；灯轴首个物理命中均是屋壳，没有依靠关闭阴影穿过基座墙。

George Street 当前镜头区域没有可核对的既有杆位；本轮未凭空添加路灯，也未提高全局环境亮度洗亮整城。普通夜街照明覆盖仍有限。歌剧院投光器的具体位置、灯具光学参数与全部灯的功率均为游戏可读性估计，不是现场测绘、照度合规报告或当前城市设施清单。室外摄影/场馆照片不能证明每一盏灯的实际配光。

## 来源与实现边界

前厅灯带依据已实际查看的 [Populous Theatre foyer N13照片](https://populous.com/uploads/2018/01/13_2932_01_N13_cropped_1440x1080-1200x900-c-center.jpg)，其他 ICC 顶棚灯组依据 [Sculptform 已安装内饰照片](https://sculptform.com/en-gb/project/icc-sydney/)，详见 [ICC参考](ICC_REFERENCE.md)。这些图像只作观察，没有复制像素进入游戏。歌剧院 [官方保护管理计划](https://www.sydneyoperahouse.com/sites/default/files/collaborodam_assets/soh-cmp-interactive-1.pdf) 说明公共门厅灯光应兼顾地面、人物可见与夜间海景；这不是上述四盏外部投光器的施工图。普通白色泛光没有复制节庆投影作品。

使用 [Godot SpotLight3D](https://docs.godotengine.org/en/stable/classes/class_spotlight3d.html) 的固定方向、范围、光锥及距离淡出，天黑只调整数值能量，不反复切换 `visible`、阴影或材质功能。无阴影近场灯属于性能折衷，可能产生局部间接漏光；本轮检测灯轴无遮挡，未声称整个光锥的每条光线都有遮挡验证。首次灯光可见时的管线成本仍须原生计数验证，不能以代码未切功能就宣称零编译或固定FPS。

## 接口与验证

主程序创建 Node3D 实例后调用 `setup(game)`，它立即使用实际 `city_clock.solar_state()`。时钟 `changed` 只包含保存状态，主程序回调需重新读取 `solar_state()` 并传入 `apply_cycle(state)`。独立0.2秒损坏检查不依赖主程序的镜头更新；结构移除后灯能量归零，修复后恢复。所有时钟/损坏更新只在数值变化时提交能量。`snapshot()` 给出实际数量、位置、支撑ID、能量、范围、光锥及功能标志；`clear()` 删除本模块对象。

独立 `source/public_lighting_test.gd` 在真实 ICC、Opera、Bridge 组件构建的 LocalWorld 中通过 **31/31 headless检查**，报告 `reports/public-lighting/checks.json` 带9份直接源码/资源哈希：固定预算、重复setup、101次昼夜数值更新、灯到前厅地板的无遮挡射线、原楼板逐碰撞顶点一致、顶面朝向与高度、四处投光器平台净空/承载/射向屋壳、破坏与修复、旧floor ID移除支撑，以及清理。没有使用用户存档，没有启动GPU或完整城市。

这31项不证明原生图像亮度、渲染性能或最终App通过。完整城市 `daylight_validation.gd` 已记录每张截图的实际灯光快照，并检查灯数量/光能与非自发光前厅材质；最终夜景须由主任务实看原生截图后验收。
