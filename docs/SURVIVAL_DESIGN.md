# 奶龙危机：玩家规则与开发契约

本模式在已有的 Godot 悉尼地图上加入“探索街区 → 清理奶龙 → 获得金币 → 治疗、维修和升级 → 继续探索”的循环。方向参考 Infection Free Zone 的真实街区战斗体验，不加入基地建设、资源生产线或基地经营，也不替换现有城市导航和昼夜系统。另有“自由观光”模式，可安静探索；战斗和人物救援规则用于“奶龙危机”；两个实际游戏模式的载具都使用有限耐久和能源。

奶龙是用户指定的既有角色。本仓库以程序化网格制作其游戏表现，不声称拥有原创角色 IP，也不因模型由代码生成而声称获得角色授权。五类敌人保持统一的圆润黄色外观，以体型、围巾、护肩、鼓腮、冠饰和攻击动作区分，不通过随意换肤色制造类别。

当前清理目标是在玩家附近动态生成的一组遭遇，不是悉尼全区的固定关卡目录。沿用地图和地标不等于完成全区 1:1、所有真实街区或公共室内复刻。

## 开始与操作

新游戏保留 50,000 金币初始资金、120 点人物生命和 3 个医疗包。开场有 25 秒整备时间，暂不生成敌人。已有存档保留余额及保存的生存进度。

| 操作 | 当前行为 |
|---|---|
| 左键 / X，步行时 | 使用脉冲枪；基础命中伤害 28，射击间隔 0.24 秒，射线距离 85 米 |
| 左键 / X，驾驶坦克或战斗机时 | 使用该载具武器，沿用瞄准、装填、弹道、爆炸与建筑破坏系统 |
| Tab | 免费新增并直接进入载具；同款耐久和火控等级继续沿用 |
| E | 进入或离开附近载具；在损毁、沉没载具中可离舱反击或游泳 |
| H | 消耗 1 个医疗包，回复最多 60 点人物生命；冷却 12 秒 |
| B | 打开维修、补给与升级面板；打开面板不等于满足交易条件 |
| Home | 呼叫救援，返回个人空间；最多扣除 500 金币 |
| M / J | 沿用地图标点导航 / 工作任务；任务收入仍可用于生存开销 |

行走、游泳、驾驶、Shift 三倍加速、Ctrl 漂移及空格急刹沿用现有控制。生存模式中，失去耐久或燃料的载具不能靠 Shift 恢复动力。脉冲枪检查摄像机瞄准与枪口到目标的路径，近处墙体也会挡住射击。

人物实际受伤后有 0.6 秒伤害间隔。敌人会攻击当前人物或正在驾驶的载具；载具承受伤害时不会同时直接扣人物生命。高速撞击敌人能造成伤害，也会损耗载具；在自己载具旁开炮存在近距离爆炸自损。坦克、战斗机和平衡车在两个实际游戏模式中都不再无损；观光模式的区别是没有奶龙遭遇。

## 敌人、等级与金币

下表是 Lv.1 基础值。“伤害”是敌人发出的基础伤害，载具装甲会进一步减伤。

| 类型 | 生命 | 伤害 | 移速（m/s） | 基础攻击距离 | 前摇 | 击败金币 |
|---|---:|---:|---:|---:|---:|---:|
| 游荡奶龙 `roamer` | 80 | 8 | 2.8 | 2 m | 0.65 s | 120 |
| 疾跑奶龙 `runner` | 60 | 7 | 6.2 | 2 m | 0.65 s | 160 |
| 重装奶龙 `brute` | 360 | 22 | 2.2 | 3 m | 1.3 s | 480 |
| 喷吐奶龙 `spitter` | 110 | 12 | 2.7 | 22 m | 1.0 s | 240 |
| 首领奶龙 `alpha` | 700 | 28 | 3.5 | 4 m | 1.5 s | 1200 |

每完成两次清理，之后生成的敌人提高一级：`等级 = clamp(1 + floor(累计清理次数 / 2), 1, 10)`。清理 0–1 次时为 Lv.1，2–3 次时为 Lv.2，以此类推，最高 Lv.10；已有敌人不会在原地突然升级。

同一类型、等级为 L 时：

- 生命上限 = 基础生命 × `1 + 0.18 × (L − 1)`。
- 伤害 = 基础伤害 × `1 + 0.06 × (L − 1)`。
- 击败金币 = 基础金币 × `1 + 0.4 × (L − 1)`，四舍五入为整数。
- 移速、体型和基础攻击距离不随等级增长。

例如，Lv.10 游荡奶龙为 209.6 生命、12.32 基础伤害、552 金币；Lv.10 首领为 1834 生命、43.12 基础伤害、5520 金币。头顶显示 `Lv.N 中文类型` 和 `击败 +N 金币`，血条与名称在远处隐藏。

击败后金币自动计入余额和累计收入，每只敌人只奖励一次；另有 20% 概率补充一个医疗包，仍受携带上限限制。喷吐会显示飞行物及落点警示，首领会高举双臂、屈身蓄力并显示“重击蓄力”和红圈。两类范围攻击在前摇后还有 0.85 秒落点警示，喷吐范围 3.2 米、首领冲击范围 4 米；移动离开或有效遮挡可以避免伤害。

敌人使用实际地面碰撞、局部绕障和视线检查。近战在前摇结束时重新确认距离与遮挡；攻击大载具按其碰撞体最近表面计算距离，不要求敌人穿进坦克或飞机中心。

## 清理循环与昼夜

每轮目标数为 `min(16, 6 + 累计清理次数 × 2)`：起初 6 只，随后 8、10、12、14，最高每轮 16 只。全局同时存活上限为 24。前两次清理后，之后每轮最后一个生成名额安排首领，其余按游荡、疾跑、喷吐、重装等组合生成。

完成一轮时，累计清理数先加一，再发放 `800 + min(累计清理次数, 6) × 150` 金币奖金。因此首次清理奖励 950，之后 1100、1250、1400、1550，六次起每轮 1700 金币；这些奖金另外叠加各敌人的击败金币。同时补充 1 个医疗包，并进入 30 秒喘息时间，停止新增敌人。

生成间隔按现有夏季昼夜系统的夜间因子，从白天约 4 秒逐渐缩短到夜间约 2.6 秒。开场整备及清理后喘息期间不生成；夜间不会绕过整备时间，也不改变每轮配额。

生成点在当前人物或载具附近约 28–58 米内寻找，优先避开正前方视野，并检查地面、坡度、附近空间和高度差。高空、深水或没有合适地面的地方不会强行在玩家身旁刷怪。超过 240 米的敌人会卸载并回补本轮生成名额，不能靠远离敌人直接领取清理奖金。这是局部遭遇机制，不是全城常驻敌人或经过逐街验证的关卡覆盖。

## 治疗、维修与升级

B 还可给当前载具补满能源，费用为 `ceil((100 − 当前能源百分比) × 3)` 金币。补能源不恢复耐久，也不补其他副本；满能源不收费，余额不足时保持原状态。

医疗包最多携带 5 个。H 使用已有医疗包不另收金币；B 面板补充每个 300 金币。满生命、冷却未结束、没有医疗包或已经进入救援时不会消耗医疗包。人物治疗不能修复载具。

B 面板允许查看状态，但维修、补给和升级都由同一个交易入口再次验证：

- 当前载具速度不超过 1 m/s（约 3.6 km/h）。
- 距上次实际受伤至少 8 秒。
- 当前人物或载具表面周围 20 米内没有存活奶龙。
- 若当前驾驶的是已落水的非船载具，先 E 离舱或 Home 救援，再申请远程维修。
- 余额足够，且该服务确有可购买的目标。

菜单暂停时冷却和脱战计时不继续流逝；需要返回游戏，在安全位置等待。救援是单独的脱困路径，不受购买服务的停稳、附近敌人条件限制。

| 服务 | 价格与效果 |
|---|---|
| 医疗包 | 300 金币 / 个，上限 5 个 |
| 同款车队维修 | `ceil((100 − 当前耐久百分比) × 30)` 金币，恢复到 100% |
| 火控 I | 8000 金币；基础伤害 +25%，装填时间为基础的 90% |
| 火控 II | 再付 16000；基础伤害 +50%，装填时间为基础的 80% |
| 火控 III | 再付 28000；基础伤害 +75%，装填时间为基础的 70% |

维修按缺少的耐久百分点收费，不是按人物生命收费。例如 60% 耐久修满需要 1200 金币，0% 修满需要 3000。火控升级只适用于当前驾驶的坦克或战斗机，最高 III 级；效果按基础值线性计算，三个价格为逐级费用。

## 同款耐久、损毁与落水

载具仍免费新增，但相同 `kind` 共享耐久和升级账本。同步耐久取该类型已有账本及实例中的最低值，升级取最高已购等级，再回写同款实例。新增、切换、保存或恢复都沿用账本，不能通过重新生成一辆同款车洗掉伤害。一个类型损毁不妨碍使用其他健康类型。

耐久为 0 的车型不能继续免费生成可用副本；需要在 B 车队列表付费维修。维修一次恢复同款车队，升级一次也应用于所有同款实例及之后新增的副本。金币不足时交易失败，不先扣钱、不产生债务。

生存模式中的坦克装甲将战斗伤害除以 6，战斗机与民航机除以 3，游艇除以 4，其余类型除以 1；它们仍可能损毁。零耐久停止推进与武器，不会因为重新入座获得发射或加速能力。

非船载具浸入水中会受到阻力、沉降和持续损耗。付费维修某车型时，已经弃置、无人驾驶且位于水面以下的该类非船残骸会被回收移除，避免它们继续在水里消耗刚修好的共享耐久；其他同款实例正常修复。之后可用 Tab 新增。快艇和游艇不按这条“落水非船残骸”规则回收。

## 救援与被击败

主动 Home 或 B 面板呼叫救援最多扣 500 金币；人物生命归零后的救援最多扣 1000。实际扣费为 `min(当前余额, 应付金额)`，余额不足时扣到 0，不欠债。

救援会退出当前载具、清除附近敌人与未结算的危险区域、恢复人物生命并送回个人空间，至少保留 1 个医疗包，给予 15 秒整备时间。余额、累计清理进度、同款耐久和火控升级保留；受损车队不会免费修好，当前轮次未击败的敌人以后还需清理。救援不是免费维修或跳过一轮的方式。

## 模块与开发契约

| 模块 | 职责与边界 |
|---|---|
| `game/scripts/harbor_survival.gd` | 生成和清理轮次、等级、目标切换、实际判伤、金币、医疗包、同款账本、交易、救援和生存存档 |
| `game/scripts/nailong_enemy.gd` | `CharacterBody3D` 接地追踪、绕障、攻击意图、前摇/冷却、独立生命、一次性死亡通知 |
| `game/scripts/nailong_model.gd` | 五型共享网格/材质、程序动作、受击和死亡表现、攻击预警；不处理金币 |
| `game/scripts/harbor_player.gd` | 人物生命、治疗、伤害间隔及 `defeated` 信号 |
| `game/scripts/harbor_vehicle.gd` | 真实载具耐久、装甲、失去动力、维修、火控等级保存；通过 `survival_enabled` 区分生存与观光 |
| `game/scripts/vehicle_weapons.gd` | 载具弹道与武器伤害，发出 `blast_hit`，火控等级修改基础伤害和冷却 |
| `game/scripts/survival_hud.gd` | 只显示状态并发出治疗/服务请求，不扣金币、不直接治疗、不直接生成敌人 |
| `game/scripts/main.gd` | 模式、H/B/武器输入、菜单、主场景和各模块整合 |

敌人接口为 `configure(type, level=1)`、`set_target(Node3D)`、`take_damage(amount, hit_position=Vector3.ZERO)` 和 `snapshot()`。`take_damage` 返回实际扣除值；非法、非正或死亡后的伤害返回 0。`defeated(enemy, reward)` 在标记死亡并关闭碰撞后只发一次；管理器也先检查敌人仍在列表中再发金币，防止同步信号重入造成重复奖励。

`attack_requested(enemy, damage, attack_range)` 只表示前摇完成，管理器必须重新检查当前模式、整备、敌人有效性、目标表面距离和视线，再造成伤害或建立落点预警。`distance_to_target_surface()` / `target_surface_point()` 对大型载具使用子碰撞形状及其实际变换；Box、Sphere、Capsule、Cylinder 使用对应形状，其余形状回退局部 AABB。不得用固定巨额距离宽限代替车体尺寸判断。

敌人碰撞层为 16、碰撞掩码为 `1 | 4`，加入 `nailong_enemies` 组并带 `enemy=true` 元数据。射击查询要包含敌人层，同时保留世界和载具遮挡。程序化外观资源可共享，血量、攻击计时、受击覆盖材质、死亡和奖励状态必须独立；不能通过修改共享黄色材质让所有敌人同时闪白。

存档 `revision=2` 保存人物生命、医疗包、治疗/脱战冷却、击败及清理计数、本轮进度、整备/喘息时间、`fleet_health`、`fleet_upgrades`，以及存活敌人的类型、位置、生命和等级。恢复时校验类型、数值和范围；缺少敌人等级按 Lv.1，等级钳制 1–10。每个敌人的 `snapshot.level` 必须传回 `configure`，再恢复剩余生命，不能按当前新轮次等级覆盖旧敌人。已死亡敌人不恢复，也不重发奖励。恢复至少给予 5 秒整备；未结算的前摇和危险区域不会作为重复伤害重播。

## HUD 状态约定

HUD 用 `setup(host)` 连接主场景，以 `update_state(data)` 接收实际状态。生命卡在左侧地区信息下方，保留地图、指南针、速度和驾驶条；名称过长时截断。鼠标被捕获时 HUD 不拦截瞄准，只有释放鼠标后 H/B 按钮接受点击；地图、暂停、弹窗及菜单打开时隐藏并禁止回调穿透。

| 字段 | 含义 |
|---|---|
| `active` | 仅实际生存游戏中为 true |
| `player_health` / `max_health` | 人物实际生命 / 上限，默认 120 |
| `vehicle_name` / `vehicle_health` | 当前载具 / 实际 0–100% 耐久，空名称代表步行 |
| `enemy_count` / `kills` | 当前遭遇存活数 / 累计击败数，不表示全城固定关卡总量 |
| `threat` | 0–1 综合威胁；不能仅凭高威胁把白天显示成夜晚 |
| `phase` / `objective` | 整备、喘息、街区清理或夜间威胁及当前等级 / 本轮目标 |
| `medkits` / `heal_cooldown` | 医疗包数量 / 实际剩余冷却秒数 |
| `hurt_amount` / `hurt_direction_label` | 受击反馈脉冲 / 实际来向；缺少方向时不伪造方向 |
| `aim_hit` | 命中事件脉冲，不替代伤害结算 |
| `reward_text` | 管理器给出的本次击败、等级与金币反馈 |

低生命只在进入状态时短暂提示，其后保持稳定标识；不持续全屏红闪。HUD 的 `heal_requested` / `service_requested` 只发请求，主系统仍要独立验证全部条件。

## 验证范围

`source/nailong_enemy_test.gd` 的当前隔离 Jolt 60 Hz 检查为 52/52：覆盖五型接地、绕障、墙体阻挡、前摇与冷却、目标离开、死亡重入、同类型资源共享与状态隔离、大型载具表面距离，以及等级、奖励、快照和首领重击意图。`--nailong-preview` 可输出五型实际引擎截图。

这些结果证明敌人模块的具体行为，不代表主界面、完整城市、交易、存档及发行包已全部通过最终验证。完整集成和发布状态应以本次实际运行报告及发布记录为准，不能从本设计文档推断。
